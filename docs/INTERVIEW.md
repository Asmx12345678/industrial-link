# Interview Notes

## 为什么不用一连接一线程？

工业现场可能存在数百或数千条长连接，绝大多数时间处于等待状态。一连接一线程会引入栈内存、上下文切换和锁竞争。当前实现使用单线程 Reactor 管理 I/O，后续可把 CPU 密集型解码交给工作线程池。

## TCP 为什么还要应用层心跳？

TCP 连接存在不代表对端应用仍健康。网络中断、NAT 状态和设备进程假死都可能产生半开连接。应用层 PING/PONG 可以明确验证设备程序是否还能处理业务消息。

## 如何处理粘包和拆包？

TCP 是字节流。每个 Session 维护独立接收缓冲区，每次 `recv` 后寻找换行符；只有完整帧才进入解析器，剩余字节保留到下一次读取。缓冲区设置 1 MiB 上限，避免恶意或异常设备无限占用内存。

## 如何保证不重复处理？

每台设备维护单调递增序号。序号不大于最后已处理序号时返回 `DUP`，不再写入遥测事件。这是会话级去重；生产环境需要将序号状态持久化，并结合设备重启 epoch。

## MQTT 与 Modbus 为什么使用桥？

桥可以隔离协议依赖、崩溃和阻塞式厂商 SDK。网关只维护统一的内部协议，MQTT Broker、PLC 轮询周期和厂商异常不会侵入 Session 核心。代价是多一个进程和一次本机网络跳转。

## 500 连接测试说明了什么？

它证明在指定机器、指定负载和短时条件下，网关能够建立 500 个 TCP 会话并处理约 4,819 条/秒、P95 约 5.53 ms。它不能证明真实弱网、跨网段、24 小时稳定性或生产可用性；这些需要更长时间、更多故障模型和真实设备验证。
